<Warning>
独立 Agent 项目是实验性的。项目 schema 和加载 API 可能会发生变化。此预览版需要包含该功能的匹配版本的 CLI 和 SDK；托管部署还需要兼容的 Enterprise 运行时。这些示例并不意味着旧的已安装版本支持此功能。
</Warning>

独立 Agent 项目定义一个 Agent，并在 kickoff 时接收其消息。YAML 是默认的脚手架格式，JSON 和 Python 是显式的替代方案。您不需要 `main.py`、Crew、Flow 或工厂函数。

## 创建项目

```shell Terminal
crewai create agent support_agent
cd support_agent
cp .env.example .env
```

在 `.env` 中为默认的 `openai/gpt-6.1-sol` 模型设置 `OPENAI_API_KEY`，然后安装并运行：

脚手架会为该模型的工具调用选择 Responses API（`api: responses`）。在 YAML/JSON 项目中，请编辑定义文件中的 `llm.model` 和 `llm.api`；Python 模板会从 `.env` 读取 `MODEL` 并选择 Responses API。

```shell Terminal
crewai install
crewai run
crewai run --inputs '{"messages":"What are the support hours?"}'
```

`crewai install` 会创建 `uv.lock`。请将其与项目一起提交。将 `.env` 保留在本地，并使用部署环境的设置来提供供应商凭据。

## 本地对话

脚手架会设置 `conversational: true`，Python 中对应 `Agent(conversational=True)`。在终端中，`crewai run` 会打开现有的对话式聊天界面。每条提交的消息都会结合会话历史使用配置的 Agent 和工具。将该标志设置为 false 可仅使用独立的 kickoff。

```shell Terminal
crewai run
```

```python
from crewai.project import load_agent_project

agent = load_agent_project("./support_agent")
agent.handle_turn("Remember that my project is Cedar Finch.")
reply = agent.handle_turn("What is my project's name?")
print(reply.raw)
```

实验性 SDK 通过 `agent.handle_turn(...)` 和 `agent.as_flow()` 公开同一会话。历史记录默认保存在内存中；如需跨进程恢复，请显式配置 Flow 持久化。每个独立对话请使用单独的 Agent 实例。`session_id` 选项用于标识/恢复 Flow 会话；它不会将单个 Agent 变成并发的多会话服务器。

## 项目结构

```text
support_agent/
├── agent.yaml
├── pyproject.toml
├── uv.lock
├── .env.example
├── .gitignore
├── README.md
├── tools/
│   ├── __init__.py
│   ├── support_hours.py
│   ├── lookup_plan.py
│   └── support_checklist.py
└── skills/
    └── .gitkeep
```

该配置型项目没有源码包。脚手架包含三个用于虚构支持服务的本地工具和一个空的 skills 目录；除了模型供应商密钥外，不需要其他服务或凭据。

生成的 `pyproject.toml` 选定 Agent 定义文件，并将配置和所有本地工具打包：

```toml
[tool.crewai]
type = "agent"
definition = "agent.yaml"

[tool.hatch.build.targets.wheel]
only-include = ["agent.yaml", "tools", "skills"]
```

## 定义 Agent

默认身份是一个通用的 CrewAI Agent。编辑 `role`、`goal` 和 `backstory` 以使其专业化。随附的支持工具仅是示例，只在相关场景中使用；对于其他用例可替换或删除它们。默认不安装任何技能。

编辑 `agent.yaml`：

```yaml
conversational: true
role: General-purpose AI agent
goal: Help users accomplish tasks accurately using the available tools and skills.
backstory: |-
  # Identity
  You are a general-purpose AI agent powered by CrewAI.

  # Customization
  Your behavior and capabilities are defined by this project's agent definition, tools, and skills. Customize these files for the user's needs. The included support tools are examples; use them only when relevant. Be clear about the capabilities available in this project and do not claim external actions without a tool result.
llm:
  model: openai/gpt-6.1-sol
  api: responses
tools:
  - custom:support_hours
  - custom:lookup_plan
  - custom:support_checklist
skills:
  - ./skills
max_iter: 8
```

这些是 Agent 构造函数的字段。请在运行时通过 `messages` 提供请求；不要在定义中添加固定的 `input` 字段。

### 选择 JSON 或 Python

```shell Terminal
crewai create agent json_support --format json
crewai create agent python_support --format python
```

JSON 脚手架会创建包含相同字段的 `agent.json`：

```json
{
  "conversational": true,
  "role": "General-purpose AI agent",
  "goal": "Help users accomplish tasks accurately using the available tools and skills.",
  "backstory": "# Identity\nYou are a general-purpose AI agent powered by CrewAI.\n\n# Customization\nYour behavior and capabilities are defined by this project's agent definition, tools, and skills. Customize these files for the user's needs. The included support tools are examples; use them only when relevant. Be clear about the capabilities available in this project and do not claim external actions without a tool result.",
  "llm": {
    "model": "openai/gpt-6.1-sol",
    "api": "responses"
  },
  "tools": [
    "custom:support_hours",
    "custom:lookup_plan",
    "custom:support_checklist"
  ],
  "skills": [
    "./skills"
  ],
  "max_iter": 8
}
```

Python 脚手架会从 `src/python_support/agent.py` 导出 `agent = Agent(...)`。当定义 Agent 需要 Python 逻辑时使用它。

`.yml` 和 `.yaml` 均受支持。重命名或移动配置文件时，请同时更新 `definition` 和 wheel 的 `only-include` 列表。定义文件的路径必须保持在项目根目录内。

如果没有显式的 `definition`，发现机制接受单个位于根目录的 `agent.py`、`agent.json`、`agent.yml` 或 `agent.yaml`，或符合约定的 `src/<package>/agent.py`。发现多个文件会产生错误；请设置 `definition` 来选择其中一个。

## 添加自定义工具

以随附的 `tools/support_hours.py` 为起点创建另一个工具：

```python
from crewai.tools import BaseTool


class SupportHoursTool(BaseTool):
    name: str = "support_hours"
    description: str = "Return the fictional service's published support hours."

    def _run(self) -> str:
        return "Support is available Monday to Friday, 09:00-17:00 UTC."
```

生成的定义会显式注册工具和技能目录；JSON 使用相同的字符串列表：

```yaml
tools:
  - custom:support_hours
  - custom:lookup_plan
  - custom:support_checklist
skills:
  - ./skills
```

`custom:support_hours` 会从 `tools/support_hours.py` 加载一个 `BaseTool` 子类。将任何工具依赖添加到 `pyproject.toml`，并使用 `crewai install` 刷新锁文件。只加载可信的项目代码：自定义工具和 Python 引用在加载期间会执行 Python 代码。

## 参考工具和技能

生成的示例使用本地的虚构数据。它们不会检查账户、重置密码、处理退款或创建工单。

| 工具 | 输入 | 结果 |
| --- | --- | --- |
| `support_hours` | 无 | 以 UTC 表示的公开支持时间 |
| `lookup_plan` | `plan`：`starter` 或 `pro` | 席位配额和支持渠道 |
| `support_checklist` | `topic`：`sign-in` 或 `billing` | 故障排除步骤 |

`skills/` 目录初始为空，仅包含 `.gitkeep` 以便在 Git 和打包构建中保留该目录。添加带有 `name` 和 `description` frontmatter 的 `skills/<name>/SKILL.md` 即可创建一个技能。添加的技能会作为元数据被发现；Agent 可以使用 `load_skill` 按需加载相关指令。

YAML/JSON 中的本地技能路径相对于项目根目录解析，包括从其他目录调用 `load_agent_project(path)` 的情况。Python 脚手架将 `tools/` 和 `skills/` 都放在 `src/<package>/` 内，并将技能锚定到 `agent.py`。wheel 和部署归档包会包含这些文件。

尝试一个组合使用示例能力的请求：

```shell Terminal
crewai run --inputs '{"messages":"I use the Pro plan and cannot sign in. Use the available tools to explain what I should try and when support is available. Write a short customer reply."}'
```

## 传递消息历史

`messages` 也接受一个非空的 role/content 消息列表：

```shell Terminal
crewai run --inputs '{"messages":[{"role":"user","content":"Use support_hours to verify the published support hours."}]}'
```

每次 kickoff 都会创建一个全新的 Agent 和普通的本地自定义工具实例。这些项目不会在 kickoff 之间自动保留对话历史。现有的任意 Python 引用可能会解析到模块级的单例对象；加载器不会隔离它们的可变状态。

对于编程方式的使用，实验性 SDK 加载器遵循相同的项目选择规则：

```python
from crewai.project import load_agent_project

agent = load_agent_project("./support_agent")
result = agent.kickoff("What are the support hours?")
print(result.raw)
```

## 验证并部署预览版

```shell Terminal
crewai deploy validate
```

YAML/JSON 验证会检查字段、Python 引用语法和工具声明，而不会执行项目的 Python 代码，也不会构造 Agent、工具或供应商客户端。Python 入口点会被导入并可能执行项目代码。验证不会运行 kickoff。常规的归档流水线包含定义文件、工具、技能和锁文件，同时排除 `.env` 和 `.venv`。

对于使用兼容预览版 Enterprise 运行时的部署，请使用 [CLI 参考](/edge/zh-CN/concepts/cli)中描述的现有部署工作流。托管 API 接受相同的输入：

```json
{"inputs": {"messages": "What are the support hours?"}}
```

## 对话式托管部署

在兼容的实验性 Enterprise 运行时中，内部 Agent 适配器会设置 `conversational = True`。聊天在每一轮都使用配置的 Agent 及其工具。先启动一个会话，然后在后续消息中复用其 `session_id`：

```http
POST /chat/start
Authorization: ******
Content-Type: application/json

{}
```

```http
POST /chat/<session_id>/message
Authorization: ******
Content-Type: application/json

{"message": "Remember that my project is Cedar Finch.", "stream": false}
```

```http
GET /chat/<session_id>/history
Authorization: ******
```

每条消息都会返回一个不同的 `kickoff_id`；请轮询 `/status/<kickoff_id>` 直到该轮完成后再发送下一条消息。会话会保留用户/助手历史，并在每一轮将其传递给一个全新的 Agent。其对话记录包含公开的回答，而执行结果保留结构化的 Agent 输出和用量信息。会话的生命周期和持久化取决于已部署运行时的存储配置。不同会话拥有各自独立的历史记录。

`POST /kickoff` 仍可用于独立执行。本地 `crewai run` 会打开聊天，而 `crewai run --inputs` 仍是单次 kickoff。脚手架会在 Agent 定义中启用对话标志；您无需编写 Flow 或 `main.py`。

此预览版已通过原生 API 和 Celery worker 进行了验证。Token 流式传输、恢复/检查点支持、一等公民的 Agent 配置，以及生产容器/发布兼容性仍不在其已验证范围之内。
