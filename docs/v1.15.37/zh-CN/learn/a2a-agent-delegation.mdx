## A2A 代理委托

<Info>
将 A2A 代理部署到生产中？有关分布式状态、企业身份验证、gRPC 传输和水平扩展，请参阅 [AMP 上的 A2A](https://docs-platform.crewai.com/platform/zh-CN/features/a2a)。
</Info>

CrewAI 将 [A2A 协议](https://a2a-protocol.org/latest/) 视为一流的委托原语，使代理能够委托任务、请求信息并与远程代理协作，并充当符合 A2A 的服务器代理。
在客户端模式下，代理根据任务要求自主选择本地执行或远程委托。

## 它是如何运作的

当代理配置了 A2A 功能时：

1. Agent 分析每个任务
2. 它决定：
   - 直接利用自身能力处理任务
   - 委托给远程 A2A 代理进行专门处理
3. 如果是委托，代理通过协议与远程A2A代理进行通信
4. 结果返回到 CrewAI 工作流程

<Note>
A2A 委托需要 `a2a-sdk` 包。安装方式：`uv add 'crewai[a2a]'` 或`pip install 'crewai[a2a]'`
</Note>

## 基本配置

<Warning>
`crewai.a2a.config.A2AConfig` 已弃用，并将在 v2.0.0 中删除。使用 `A2AClientConfig` 连接到远程代理和/或使用 `A2AServerConfig` 将代理公开为服务器。
</Warning>

通过设置 `a2a` 参数来配置 A2A 委派代理：

```python Code
from crewai import Agent, Crew, Task
from crewai.a2a import A2AClientConfig

agent = Agent(
    role="Research Coordinator",
    goal="Coordinate research tasks efficiently",
    backstory="Expert at delegating to specialized research agents",
    llm="gpt-4o",
    a2a=A2AClientConfig(
        endpoint="https://example.com/.well-known/agent-card.json",
        timeout=120,
        max_turns=10
    )
)

task = Task(
    description="Research the latest developments in quantum computing",
    expected_output="A comprehensive research report",
    agent=agent
)

crew = Crew(agents=[agent], tasks=[task], verbose=True)
result = crew.kickoff()
```

## 客户端配置选项

`A2AClientConfig` 类接受以下参数：

<ParamField path="endpoint" type="str" required>
A2A 代理端点 URL（通常指向 `.well-known/agent-card.json`）
</ParamField>

<ParamField path="auth" type="AuthScheme" default="None">
A2A 代理的身份验证方案。支持 Bearer 令牌、OAuth2、API 密钥和 HTTP 身份验证。
</ParamField>

<ParamField path="timeout" type="int" default="120">
请求超时（以秒为单位）
</ParamField>

<ParamField path="max_turns" type="int" default="10">
与 A2A 代理的最大对话轮数
</ParamField>

<ParamField path="response_model" type="type[BaseModel]" default="None">
可选的 Pydantic 模型，用于请求 A2A 代理的结构化输出。 A2A协议不
强制执行此操作，因此 A2A 代理无需满足此请求。
</ParamField>

<ParamField path="fail_fast" type="bool" default="True">
如果代理连接失败，是否立即引发错误。当 `False` 时，代理将继续使用可用的代理，并通知 LLM 不可用的代理。
</ParamField>

<ParamField path="trust_remote_completion_status" type="bool" default="False">
当`True`时，A2A代理在发出完成信号时直接返回结果。当 `False` 时，允许服务器代理查看结果并可能继续对话。
</ParamField>

<ParamField path="updates" type="UpdateConfig" default="StreamingConfig()">
接收任务状态的更新机制。选项：`StreamingConfig`、`PollingConfig` 或 `PushNotificationConfig`。
</ParamField>

<ParamField path="accepted_output_modes" type="list[str]" default='["application/json"]'>
客户端可以在响应中接受的媒体类型。
</ParamField>

<ParamField path="extensions" type="list[str]" default="[]">
客户端支持的 A2A 协议扩展 URI。
</ParamField>

<ParamField path="client_extensions" type="list[A2AExtension]" default="[]">
用于工具注入、提示增强和响应修改的客户端处理挂钩。
</ParamField>

<ParamField path="transport" type="ClientTransportConfig" default="ClientTransportConfig()">
传输配置，包括首选传输、支持的协商传输以及特定于协议的设置（gRPC 消息大小、keepalive 等）。
</ParamField>

<ParamField path="transport_protocol" type="Literal['JSONRPC', 'GRPC', 'HTTP+JSON']" default="None">
**已弃用**：使用 `transport=ClientTransportConfig(preferred=...)` 代替。
</ParamField>

<ParamField path="supported_transports" type="list[str]" default="None">
**已弃用**：使用 `transport=ClientTransportConfig(supported=...)` 代替。
</ParamField>

## 多个 A2A 代理

通过传递列表来配置多个 A2A 代理进行委派：

```python Code
from crewai.a2a import A2AClientConfig
from crewai.a2a.auth import BearerTokenAuth

agent = Agent(
    role="Multi-Agent Coordinator",
    goal="Coordinate with multiple specialized agents",
    backstory="Expert at delegating to the right specialist",
    llm="gpt-4o",
    a2a=[
        A2AClientConfig(
            endpoint="https://research.example.com/.well-known/agent-card.json",
            timeout=120
        ),
        A2AClientConfig(
            endpoint="https://data.example.com/.well-known/agent-card.json",
            auth=BearerTokenAuth(token="data-token"),
            timeout=90
        )
    ]
)
```

LLM将根据任务要求自动选择委托给哪个A2A代理。

## 错误处理

使用 `fail_fast` 参数控制代理连接失败的处理方式：

```python Code
from crewai.a2a import A2AClientConfig

# Fail immediately on connection errors (default)
agent = Agent(
    role="Research Coordinator",
    goal="Coordinate research tasks",
    backstory="Expert at delegation",
    llm="gpt-4o",
    a2a=A2AClientConfig(
        endpoint="https://research.example.com/.well-known/agent-card.json",
        fail_fast=True
    )
)

# Continue with available agents
agent = Agent(
    role="Multi-Agent Coordinator",
    goal="Coordinate with multiple agents",
    backstory="Expert at working with available resources",
    llm="gpt-4o",
    a2a=[
        A2AClientConfig(
            endpoint="https://primary.example.com/.well-known/agent-card.json",
            fail_fast=False
        ),
        A2AClientConfig(
            endpoint="https://backup.example.com/.well-known/agent-card.json",
            fail_fast=False
        )
    ]
)
```

当`fail_fast=False`时：
- 如果某些代理失败，LLM会获知哪些代理不可用，并可以委派给正在工作的代理
- 如果所有代理均失败，LLM 会收到代理不可用的通知并直接处理任务
- 连接错误被捕获并包含在上下文中，以便做出更好的决策

## 将代理公开为 A2A 服务器

您可以将 CrewAI 代理公开为 A2A 兼容服务器，允许其他 A2A 客户端将任务委派给它们。

### 服务器配置

将 `A2AServerConfig` 添加到您的代理以启用服务器功能：

```python a2a_server_agent.py lines
from crewai import Agent
from crewai.a2a import A2AServerConfig

agent = Agent(
    role="Data Analyst",
    goal="Analyze datasets and provide insights",
    backstory="Expert data scientist with statistical analysis skills",
    llm="gpt-4o",
    a2a=A2AServerConfig(url="https://your-server.com")
)
```

### 组合客户端和服务器

通过提供两种配置，代理可以充当客户端和服务器：

```python Code
from crewai import Agent
from crewai.a2a import A2AClientConfig, A2AServerConfig

agent = Agent(
    role="Research Coordinator",
    goal="Coordinate research and serve analysis requests",
    backstory="Expert at delegation and analysis",
    llm="gpt-4o",
    a2a=[
        A2AClientConfig(
            endpoint="https://specialist.example.com/.well-known/agent-card.json",
            timeout=120
        ),
        A2AServerConfig(url="https://your-server.com")
    ]
)
```

### 文件输入和结构化输出

A2A 支持双向传递文件和请求结构化输出。

**客户端**：委派给远程 A2A 代理时，任务 `input_files` 中的文件将在传出消息中作为 `FilePart` 发送。如果在 `A2AClientConfig` 上设置了 `response_model`，则 Pydantic 模型的 JSON 模式将嵌入到消息元数据中，请求远程代理的结构化输出。

**服务器端**：传入的`FilePart`被提取并作为`input_files`传递给代理的任务。如果客户端包含 JSON 架构，服务器会从中创建响应模型并将其应用于任务。当代理返回结构化数据时，响应将以 `DataPart` 形式发回，而不是纯文本。

## 支持的身份验证方法

- **不记名令牌** - 简单的基于令牌的身份验证
- **OAuth2 客户端凭证** - 用于机器对机器通信的 OAuth2 流程
- **OAuth2 授权代码** - 需要用户授权的 OAuth2 流程
- **API 密钥** - 基于密钥的身份验证（标头、查询参数或 cookie）
- **HTTP 基本** - 用户名/密码身份验证
- **HTTP Digest** - 摘要式身份验证（需要 `httpx-auth` 包）
