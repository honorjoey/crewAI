## 概述

CrewAI 为需要的不仅仅是纯文本块的运行时公开了基于帧的流合同。该合约为 Flow 生命周期事件、直接 LLM 代币、工具活动、对话消息和自定义事件发出有序的 `StreamFrame` 对象。

当您正在构建 UI、服务桥、终端应用程序或部署运行时，并且在 Flow、聊天轮次或直接 LLM 调用运行时需要稳定的结构化事件流时，请使用此 API。

## 流帧

每个帧都有相同的信封：

```python
from crewai.types.streaming import StreamFrame

frame.id           # unique frame id
frame.seq          # execution-local order, when available
frame.type         # source event type, such as "flow_started"
frame.channel      # "llm", "flow", "tools", "messages", "lifecycle", or "custom"
frame.namespace    # source/runtime namespace
frame.timestamp    # event timestamp
frame.parent_id    # parent event id, when available
frame.previous_id  # previous event id, when available
frame.data         # event payload
frame.event        # alias for frame.data
frame.content      # printable text for token-like frames, otherwise ""
```

`channel` 字段是在消费者中路由帧的最快方式：

| 渠道 | 包含 |
|---------|----------|
| `llm` | LLM 流媒体活动的令牌和思考块 |
| `flow` | 流程生命周期、方法执行、路由和暂停/恢复事件 |
| `tools` | 工具使用事件 |
| `messages` | 对话记录事件 |
| `lifecycle` | 不特定于另一个通道的运行时生命周期事件 |
| `custom` | 未映射到内置通道的事件 |

`frame.type` 保留源事件类型，因此消费者可以处理通道内的特定事件。

## 流式传输

在 Flow 上设置 `stream=True` 以使 `kickoff()` 返回流会话：

```python
from crewai.flow import Flow, start


class ReportFlow(Flow):
    @start()
    def generate(self):
        return "done"


flow = ReportFlow(stream=True)
stream = flow.kickoff()

with stream:
    for chunk in stream:
        print(chunk.content, end="", flush=True)
        if chunk.type == "tool_usage_started":
            print(chunk.event["tool_name"])

result = stream.result
```

您必须在读取`stream.result` 之前消耗该流。尽早访问结果会引发`RuntimeError`，因此消费者不会意外地将部分运行视为已完成。

当您希望对单次调用进行流式传输时，您还可以直接调用 `flow.stream_events(...)`，而不需要在 Flow 实例上设置 `stream=True`。

## 按频道过滤

`StreamSession` 公开通道投影，以保留所选通道内的全局帧顺序：

```python
stream = flow.stream_events()

with stream:
    for frame in stream.llm:
        print(frame.content, end="", flush=True)

result = stream.result
```

可用的预测有：

| 投影 | 镜框 |
|------------|--------|
| `stream.events` | 所有帧 |
| `stream.llm` | LLM框架 |
| `stream.messages` | 对话消息帧 |
| `stream.flow` | 流程框架 |
| `stream.tools` | 工具架 |
| `stream.interleave([...])` | 一组选定的通道 |

当消费者只需要某些频道但仍需要其相对顺序时，请使用`stream.interleave(["flow", "llm", "messages"])`。

## 异步流式传输

对异步消费者使用`astream()`：

```python
flow = ReportFlow()
stream = flow.astream()

async with stream:
    async for chunk in stream.events:
        print(chunk.channel, chunk.type, chunk.content)

result = stream.result
```

异步会话与同步会话具有相同的投影。

## 直播直接 LLM 通话

`llm.call(...)` 仍然返回最终的组装结果。当您想要在块到达时对其进行迭代并同时保留结构化事件负载时，请使用`llm.stream_events(...)`：

```python
from crewai import LLM


llm = LLM(model="gpt-4o-mini")
stream = llm.stream_events(
    messages=[
        {
            "role": "user",
            "content": "Explain CrewAI streaming in two short sentences.",
        }
    ]
)

with stream:
    for chunk in stream:
        print(chunk.content, end="", flush=True)

result = stream.result
```

`llm.stream_events(...)` 暂时启用包装调用的流式传输，然后恢复 LLM 之前的 `stream` 设置。提供商集成继续发出底层 LLM 流事件；这个助手为每个 LLM 提供商提供了针对这些事件的通用迭代器 API。

## 对话轮流

对话流可以使用 `stream_turn()` 流式传输一个用户回合：

```python
from crewai import Flow
from crewai.flow import ConversationConfig, ConversationState


@ConversationConfig(llm="gpt-4o-mini", defer_trace_finalization=True)
class ChatFlow(Flow[ConversationState]):
    conversational = True


flow = ChatFlow()
stream = flow.stream_turn("What can you help me with?", session_id="session-1")

with stream:
    for frame in stream.events:
        if frame.channel == "llm" and frame.type == "llm_stream_chunk":
            print(frame.content, end="", flush=True)

reply = stream.result
```

在`stream_turn()`期间，内置对话应答路径启用该回合的LLM令牌流，并随后恢复LLM之前的`stream`设置。如果创建自己的代理或 LLM 实例的自定义路由处理程序需要令牌级输出，则应将这些 LLM 配置为流式传输。

## 清理

尽可能使用会话作为上下文管理器。如果客户端在流耗尽之前断开连接，请显式关闭会话：

```python
stream = flow.stream_events()

try:
    for frame in stream.events:
        print(frame.type)
finally:
    if not stream.is_exhausted:
        stream.close()
```

对于异步流，请使用`await stream.aclose()`。

## 传统的块流

使用 `stream=True` 的 Crew 流仍然返回 [Streaming Crew 执行](/zh-CN/learn/streaming-crew-execution) 中描述的面向块的 `CrewStreamingOutput` API。直接`llm.call(...)`仍然返回最终的LLM结果。框架契约适用于需要跨流、直接 LLM 调用、对话轮次、工具和消息的稳定事件包络的运行时。
