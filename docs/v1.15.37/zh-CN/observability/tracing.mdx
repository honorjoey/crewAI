# CrewAI 内置追踪
CrewAI 提供内置跟踪功能，使您可以实时监控和调试 Crews 和 Flows。本指南演示如何使用 CrewAI 的集成可观察性平台启用**Crews**和**Flows**的跟踪。
>**什么是 CrewAI Tracing？**CrewAI 的内置跟踪为您的 AI 代理提供全面的可观察性，包括代理决策、任务执行时间表、工具使用和 LLM 调用 - 所有这些都可以通过 [CrewAI AMP 平台](https://app.crewai.com) 访问。跟踪的管理独立于[遥测](/zh-CN/telemetry)。
![CrewAI 追踪接口](/images/crewai-tracing.png)
## 先决条件
在使用 CrewAI 跟踪之前，您需要：
1. **CrewAI AMP 帐户**：在 [app.crewai.com](https://app.crewai.com) 注册免费帐户
2. **CLI 身份验证**：使用 CrewAI CLI 来验证您的本地环境
```bash
crewai login
```

## 设置说明
### 第 1 步：创建您的 CrewAI AMP 帐户
访问 [app.crewai.com](https://app.crewai.com) 并创建您的免费帐户。这将使您能够访问 CrewAI AMP 平台，您可以在其中查看跟踪、指标并管理您的工作人员。
### 步骤 2：安装 CrewAI CLI 并进行身份验证
如果您尚未安装 CrewAI，请使用 CLI 工具安装：
```bash
uv add 'crewai[tools]'
```

然后使用您的 CrewAI AMP 帐户验证您的 CLI：
```bash
crewai login
```

该命令将：
1.打开浏览器进入认证页面
2. 提示您输入设备代码
3. 使用您的 CrewAI AMP 帐户验证您的本地环境
4. 为本地开发启用跟踪功能
### 第 3 步：启用船员追踪
您可以通过将 `tracing` 参数设置为 `True` 来为 Crew 启用跟踪：
```python
from crewai import Agent, Crew, Process, Task
from crewai_tools import SerperDevTool

# Define your agents
researcher = Agent(
    role="Senior Research Analyst",
    goal="Uncover cutting-edge developments in AI and data science",
    backstory="""You work at a leading tech think tank.
    Your expertise lies in identifying emerging trends.
    You have a knack for dissecting complex data and presenting actionable insights.""",
    verbose=True,
    tools=[SerperDevTool()],
)

writer = Agent(
    role="Tech Content Strategist",
    goal="Craft compelling content on tech advancements",
    backstory="""You are a renowned Content Strategist, known for your insightful and engaging articles.
    You transform complex concepts into compelling narratives.""",
    verbose=True,
)

# Create tasks for your agents
research_task = Task(
    description="""Conduct a comprehensive analysis of the latest advancements in AI in 2024.
    Identify key trends, breakthrough technologies, and potential industry impacts.""",
    expected_output="Full analysis report in bullet points",
    agent=researcher,
)

writing_task = Task(
    description="""Using the insights provided, develop an engaging blog
    post that highlights the most significant AI advancements.
    Your post should be informative yet accessible, catering to a tech-savvy audience.""",
    expected_output="Full blog post of at least 4 paragraphs",
    agent=writer,
)

# Enable tracing in your crew
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    process=Process.sequential,
    tracing=True,  # Enable built-in tracing
    verbose=True
)

# Execute your crew
result = crew.kickoff()
```

### 步骤 4：在流程中启用跟踪
同样，您可以启用 CrewAI Flows 的跟踪：
```python
from crewai.flow.flow import Flow, listen, start
from pydantic import BaseModel

class ExampleState(BaseModel):
    counter: int = 0
    message: str = ""

class ExampleFlow(Flow[ExampleState]):
    def __init__(self):
        super().__init__(tracing=True)  # Enable tracing for the flow

    @start()
    def first_method(self):
        print("Starting the flow")
        self.state.counter = 1
        self.state.message = "Flow started"
        return "continue"

    @listen("continue")
    def second_method(self):
        print("Continuing the flow")
        self.state.counter += 1
        self.state.message = "Flow continued"
        return "finish"

    @listen("finish")
    def final_method(self):
        print("Finishing the flow")
        self.state.counter += 1
        self.state.message = "Flow completed"

# Create and run the flow with tracing enabled
flow = ExampleFlow(tracing=True)
result = flow.kickoff()
```

### 步骤 5：在 CrewAI AMP 仪表板中查看跟踪
仅在成功通过身份验证的导出或明确批准的匿名上传后才会上传跟踪。本地缓冲区被丢弃的运行没有上传的跟踪。
对于与您的帐户关联的跟踪，请打开 [CrewAI AMP 仪表板中的“跟踪”选项卡](https://app.crewai.com/crewai_plus/trace_batches) 以查看代理交互、工具使用情况和 LLM 调用。
![CrewAI 追踪接口](/images/view-traces.png)
### 替代方案：环境变量配置
您还可以通过设置环境变量来启用全局跟踪：
```bash
export CREWAI_TRACING_ENABLED=true
```

或者将其添加到您的 `.env` 文件中：
```env
CREWAI_TRACING_ENABLED=true
```

设置此环境变量后，即使没有显式设置 `tracing=True`，所有 Crew 和 Flow 也会自动启用跟踪。
## 在第一次运行后查看跟踪
第一次运行 Crew 或 Flow 时，交互式终端可能会询问：
```text
Share this execution trace with CrewAI? [y/N]
```

选择**yes**将缓冲的跟踪上传到 CrewAI。痕迹可能包含
提示、输入和输出。拒绝、超时或无缘无故地运行
交互式同意提示会丢弃缓冲区。您可以稍后更改跟踪
使用 `crewai traces enable` 或 `crewai traces disable`，或通过设置 `tracing`
在 Crew 或 Flow 上。
### 本地缓冲和经过身份验证的导出
首次运行的跟踪收集将保留在进程内存中，直到您同意共享，
即使您已保存登录凭据。未经身份验证的跟踪使用相同的
同意流程。在同意之前，CrewAI 不请求任何上传授权，也不发送任何内容
执行跨度。
缓冲区最多保留**1,000 个跨度**和**8 MiB 编码的 OTLP 数据**。
设置 `CREWAI_EPHEMERAL_TRACE_MAX_SPANS` 和
`CREWAI_EPHEMERAL_TRACE_MAX_BYTES` 为正整数以调整这些限制。
溢出会丢弃最旧的跨度；大于字节限制的跨度将被丢弃。
缓冲区在共享或丢弃后被清除。
当启用跟踪并且凭证可用时，CrewAI 会交换您的
CLI 登录、`CREWAI_USER_PAT` 或 AMP 的平台集成凭据
执行特定的补助金。然后它将 OpenTelemetry span 直接导出到
码头使用该补助金。无效凭据不会退回到匿名上传。
### 托管执行会话
主机可以使用 `telemetry_session` 包装执行
`crewai.telemetry.tracing`。该会话使用 CrewAI 生命周期事件来创建
并完成跨度，保留它们的时间戳、父关系和 HITL
暂停/恢复链接。通过 `providers=` 传递现有提供商以保留
主机的跟踪器和日志记录集成。使用 `processors=` 通过跨度处理器
以及带有 `log_emitter=` 的主机日志记录回调。主机拥有任何修订内容
在这些整合中。
每个会话都拥有其跟踪生命周期并离开应用程序的全局
OpenTelemetry 提供程序未更改。
## 查看您的痕迹
### 访问 CrewAI AMP 仪表板
1.访问[app.crewai.com](https://app.crewai.com)并登录您的帐户
2. 导航到您的项目仪表板
3.点击**Traces**选项卡查看执行详情
### 你会在痕迹中看到什么
CrewAI 跟踪提供了以下方面的全面可见性：
- **代理决策**：了解代理如何推理任务并做出决策
- **任务执行时间线**：任务序列和依赖关系的可视化表示
- **工具使用**：监控调用了哪些工具及其结果
- **LLM 通话**：跟踪所有语言模型交互，包括提示和响应
- **性能指标**：执行时间、代币使用和成本
- **错误跟踪**：详细的错误信息和堆栈跟踪
### 跟踪特征
- **执行时间轴**：点击执行的不同阶段
- **详细日志**：访问全面日志以进行调试
- **性能分析**：分析执行模式并优化性能
- **导出功能**：下载轨迹以进行进一步分析
### 身份验证问题
如果您遇到身份验证问题：
1. 确保您已登录：`crewai login`
2. 检查您的互联网连接
3. 在 [app.crewai.com](https://app.crewai.com) 验证您的帐户
### 痕迹未出现
如果仪表板中未显示痕迹：
1. 确认 `tracing=True` 已在您的 Crew/Flow 中设置
2. 如果使用环境变量，请检查 `CREWAI_TRACING_ENABLED=true`
3. 对于经过身份验证的导出，请验证您的 CLI 登录名、`CREWAI_USER_PAT` 或平台集成凭证。对于匿名共享，明确批准同意提示；不需要登录
4. 验证您的工作人员/流程已执行并且跟踪导出成功。拒绝同意、超时或在没有交互式同意提示的情况下运行会丢弃本地缓冲区而不上传它
