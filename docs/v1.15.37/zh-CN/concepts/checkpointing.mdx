## 说明

### 什么是检查点

检查点会捕获 CrewAI 在运行中途重建一次运行所需的状态：crew、flow 或 agent 的完整状态——配置、agent 的记忆与知识源、task 进度、中间输出、内部状态与属性——以及 kickoff 输入、截至该时刻的事件历史，还有一个将该检查点与其所属运行关联起来的 lineage ID。回调仅以具名函数引用的形式保存；参见[恢复不会带回的内容](#恢复不会带回的内容)。

恢复会重建该状态并继续执行。已完成的 task 会被跳过，记忆与知识会被重新加载，后续工作会基于原始运行产生的相同输出继续进行。分叉执行同样的恢复流程，但使用新的 lineage，因此新分支与原始运行可以并行写入各自的检查点而不会相互覆盖。

### 检查点何时写入

检查点由事件驱动。运行时会订阅你通过 `on_events` 选择的事件，并在每次事件触发时写入一个检查点。默认的 `task_completed` 会为每个完成的 task 生成一个检查点——这是在粒度与磁盘占用之间的合理折中。像 `llm_call_completed` 这样的高频事件可用于更细粒度的恢复，但会写入多得多的文件。

### 存储

CrewAI 内置两种提供器：

- `JsonProvider` 为每个检查点写入一个文件。人类可读，易于查看。
- `SqliteProvider` 写入单个 SQLite 数据库。更适合高频检查点场景。

当设置了 `max_checkpoints` 时，两者都会清理最旧的检查点。

<Note>
自动检查点写入（事件驱动）采用尽力而为策略：写入失败会被记录日志，运行继续。手动调用 `state.checkpoint()` 和 `state.acheckpoint()` 在失败时会重新抛出异常。
</Note>

### 继承模型

`Crew`、`Flow` 和 `Agent` 都接受一个 `checkpoint` 参数。子级会从父级继承设置，除非它们自行设置了值，或传入 `False` 来选择退出。只需在 crew 上启用一次检查点，所有 agent 都会参与；也可以选择性地排除某个 agent。

### 恢复不会带回的内容

恢复操作会根据检查点文件构建 crew、flow 或 agent，而不是基于你调用 `kickoff()` 的那个对象。`crew.kickoff(from_checkpoint=...)` 运行的是文件中保存的 crew，因此你在 `crew` 上设置的可调用对象不会被复制过来。

检查点会将回调保存为模块级函数的点路径，例如 `"my_project.hooks.on_task_done"`，并在恢复时重新导入。检查点本质上是数据，所以只有在设置了 `CREWAI_DESERIALIZE_CALLBACKS=1` 环境变量时，CrewAI 才会导入这些路径。若未设置，恢复一个包含回调名称的检查点会抛出 `ValueError`。请只对你信任的检查点文件设置该变量。

以下内容不会被保存，恢复后也不会运行：

- Lambda、闭包、绑定方法（如 `notifier.on_task_done`）、`functools.partial` 对象以及可调用实例。当你将此类对象传给 `Task`、`Agent`、`Crew` 或工具时，CrewAI 会发出 `A ... callback cannot be saved in a checkpoint` 的警告；事后直接设置属性则不会警告。此类工具 `cache_function` 恢复后会变成一个永不缓存的函数。
- 可调用的 guardrail。CrewAI 在写入检查点时会发出警告。字符串形式的 guardrail 会被保存。
- `@CrewBase` 类上的 `@before_kickoff` 和 `@after_kickoff` 钩子。

若要保留无法保存的回调，请使用 `Crew.from_checkpoint()` 进行恢复，并在调用 `kickoff()` 前重新赋值：

```python
from crewai import CheckpointConfig, Crew


class Notifier:
    def on_task_done(self, output):
        print(f"Finished: {output.description}")


notifier = Notifier()
crew = Crew.from_checkpoint(
    CheckpointConfig(restore_from="./.checkpoints/<timestamp>_<uuid>.json")
)
crew.tasks[-1].callback = notifier.on_task_done
result = crew.kickoff()
```

## 教程: 恢复失败的 crew

本演练大约需要 5 分钟。你将运行一个包含两个 task 的 crew，在中途终止它，然后从保存的检查点恢复。

<Steps>
  <Step title="创建启用检查点的 crew">
    ```python
    from crewai import Agent, Crew, Task

    researcher = Agent(role="Researcher", goal="Research", backstory="Expert")
    writer = Agent(role="Writer", goal="Write", backstory="Expert")

    crew = Crew(
        agents=[researcher, writer],
        tasks=[
            Task(description="Research AI trends", agent=researcher, expected_output="bullets"),
            Task(description="Write a summary", agent=writer, expected_output="paragraph"),
        ],
        checkpoint=True,
    )
    ```
  </Step>
  <Step title="运行并在第一个 task 完成后中断">
    ```python
    result = crew.kickoff()
    ```

    在第一个 task 完成后按下 `Ctrl+C`。查看 `./.checkpoints/` 目录——名为 `<timestamp>_<uuid>.json` 的文件就是检查点。
  </Step>
  <Step title="从检查点恢复">
    ```python
    from crewai import CheckpointConfig

    result = crew.kickoff(
        from_checkpoint=CheckpointConfig(
            restore_from="./.checkpoints/<timestamp>_<uuid>.json",
        ),
    )
    ```

    研究 task 会被跳过，写作 agent 基于已保存的研究输出继续执行，crew 完成运行。

    <Note>
    恢复后的 crew 是根据检查点文件构建的，而不是 `crew` 对象。如果你的 task 使用了回调，请阅读[恢复不会带回的内容](#恢复不会带回的内容)。
    </Note>
  </Step>
</Steps>

## 操作指南

<AccordionGroup>
  <Accordion title="使用默认设置启用检查点" icon="play">
    ```python
    crew = Crew(agents=[...], tasks=[...], checkpoint=True)
    ```

    在每次 `task_completed` 时写入 `./.checkpoints/`。
  </Accordion>

  <Accordion title="自定义存储与频率" icon="sliders">
    ```python
    from crewai import Crew, CheckpointConfig

    crew = Crew(
        agents=[...],
        tasks=[...],
        checkpoint=CheckpointConfig(
            location="./my_checkpoints",
            on_events=["task_completed", "crew_kickoff_completed"],
            max_checkpoints=5,
        ),
    )
    ```
  </Accordion>

  <Accordion title="选择存储提供器" icon="database">
    <CodeGroup>
    ```python JsonProvider
    from crewai import Crew, CheckpointConfig
    from crewai.state import JsonProvider

    crew = Crew(
        agents=[...],
        tasks=[...],
        checkpoint=CheckpointConfig(
            location="./my_checkpoints",
            provider=JsonProvider(),
            max_checkpoints=5,
        ),
    )
    ```
    ```python SqliteProvider
    from crewai import Crew, CheckpointConfig
    from crewai.state import SqliteProvider

    crew = Crew(
        agents=[...],
        tasks=[...],
        checkpoint=CheckpointConfig(
            location="./.checkpoints.db",
            provider=SqliteProvider(),
            max_checkpoints=50,
        ),
    )
    ```
    </CodeGroup>

    <Tip>
    SQLite 启用了 WAL 日志模式以支持并发读取。高频检查点场景建议优先使用它。
    </Tip>
  </Accordion>

  <Accordion title="让某个 agent 退出检查点" icon="user-slash">
    ```python
    crew = Crew(
        agents=[
            Agent(role="Researcher", ...),
            Agent(role="Writer", ..., checkpoint=False),
        ],
        tasks=[...],
        checkpoint=True,
    )
    ```
  </Accordion>

  <Accordion title="分叉到新分支" icon="code-branch">
    `fork()` 会在全新的 lineage 下恢复检查点，使新运行不会与原始运行发生冲突。

    ```python
    config = CheckpointConfig(restore_from="./my_checkpoints/<file>.json")
    crew = Crew.fork(config, branch="experiment-a")
    result = crew.kickoff(inputs={"strategy": "aggressive"})
    ```

    `branch` 标签是可选的；省略时会自动生成一个。
  </Accordion>

            def step_two(self, data):
                return process(data)

  <Accordion title="手动写入检查点" icon="code">
    在任意事件上注册处理函数并调用 `state.checkpoint()`。

    <CodeGroup>
    ```python Sync
    from __future__ import annotations

    from typing import TYPE_CHECKING, Any

    from crewai.events.event_bus import crewai_event_bus
    from crewai.events.types.llm_events import LLMCallCompletedEvent

    if TYPE_CHECKING:
        from crewai.state.runtime import RuntimeState


    @crewai_event_bus.on(LLMCallCompletedEvent)
    def on_llm_done(source: Any, event: LLMCallCompletedEvent, state: RuntimeState) -> None:
        path = state.checkpoint("./my_checkpoints")
        print(f"Saved checkpoint: {path}")
    ```
    ```python Async
    from __future__ import annotations

    from typing import TYPE_CHECKING, Any

    from crewai.events.event_bus import crewai_event_bus
    from crewai.events.types.llm_events import LLMCallCompletedEvent

    if TYPE_CHECKING:
        from crewai.state.runtime import RuntimeState


    @crewai_event_bus.on(LLMCallCompletedEvent)
    async def on_llm_done_async(source: Any, event: LLMCallCompletedEvent, state: RuntimeState) -> None:
        path = await state.acheckpoint("./my_checkpoints")
        print(f"Saved checkpoint: {path}")
    ```
    </CodeGroup>

    当处理函数接受三个参数时，`state` 参数会被自动传入。完整事件目录参见[事件监听器](/zh-CN/concepts/event-listener)。
  </Accordion>

## 参考

### `CheckpointConfig`

<ParamField path="location" type="str" default='"./.checkpoints"'>
  存储目标位置。对 `JsonProvider` 是一个目录，对 `SqliteProvider` 是数据库文件路径。
</ParamField>

<ParamField path="on_events" type='list[CheckpointEventType | Literal["*"]]' default='["task_completed"]'>
  触发检查点的事件类型。`CheckpointEventType` 是一个 `Literal`——类型检查器会提供自动补全并拒绝不支持的值。完整列表参见[事件类型](#事件类型)。
</ParamField>

<ParamField path="provider" type="BaseProvider" default="JsonProvider()">
  存储后端。`JsonProvider` 或 `SqliteProvider`。
</ParamField>

<ParamField path="max_checkpoints" type="int | None" default="None">
  保留的最大检查点数量。每次写入后清理最旧的检查点。
</ParamField>

<ParamField path="restore_from" type="Path | str | None" default="None">
  通过 `from_checkpoint` 传入时要恢复的检查点。
</ParamField>

### `checkpoint` 字段取值

`Crew`、`Flow` 和 `Agent` 均接受此字段。

<ParamField path="None" type="default">
  从父级继承。
</ParamField>

<ParamField path="True" type="bool">
  使用默认设置启用。
</ParamField>

<ParamField path="False" type="bool">
  显式选择退出。阻断继承。
</ParamField>

<ParamField path="CheckpointConfig(...)" type="CheckpointConfig">
  自定义配置。
</ParamField>

### 事件类型

`on_events` 接受任意组合的 `CheckpointEventType` 值。默认的 `["task_completed"]` 会为每个完成的 task 写入一个检查点；`["*"]` 匹配所有事件。

<Warning>
`["*"]` 以及 `llm_call_completed` 等高频事件会写入大量检查点，可能降低性能。请配合 `max_checkpoints` 使用。
</Warning>

<Expandable title="所有支持的事件">

### 存储提供器

<ParamField path="JsonProvider" type="provider">
  每个检查点一个文件，位于 `location` 目录内，命名为 `<timestamp>_<uuid>.json`。
</ParamField>

<ParamField path="SqliteProvider" type="provider">
  位于 `location` 的单个数据库文件，使用 WAL 日志。
</ParamField>
