## 概述

CrewAI 可以在两个层面进行规划：

- **Agent 规划**：agent 为自己的工作撰写分步计划，然后逐步执行并检查每一步。通过 `Agent(planning_config=PlanningConfig(...))` 进行配置。
- **Crew 规划**：在 crew 运行之前，`CrewPlanner` 为每个 task 撰写计划并将其添加到各 task 的描述中。通过 `Crew(planning=True)` 启用。

你可以单独使用其中一种，也可以同时使用两种。

## Agent 规划

向 agent 传入 `PlanningConfig` 以启用规划：

```python
from crewai import Agent, Crew, PlanningConfig, Task

analyst = Agent(
    role="Market Analyst",
    goal="Explain market trends with clear evidence",
    backstory="You are an experienced analyst who breaks big questions into small, checkable steps.",
    planning_config=PlanningConfig(
        reasoning_effort="medium",
        max_attempts=3,
    ),
)

trends_task = Task(
    description="Identify the three most important trends in electric vehicle adoption over the last five years.",
    expected_output="A short report describing the top 3 trends, with one supporting fact for each.",
    agent=analyst,
)

crew = Crew(agents=[analyst], tasks=[trends_task])
result = crew.kickoff()

print(result)
```

只要提供了 `PlanningConfig`，规划就会开启。若要关闭，请不要设置 `planning_config`。

### 工作原理

当 agent 开始执行 task 时，它会运行一个"规划-执行"循环：

1. **规划。**规划 LLM 撰写计划，并被要求保持在 `max_steps` 步以内，同时说明计划是否就绪。
2. **完善。**如果计划尚未就绪，规划器会持续完善，直到就绪或达到 `max_attempts`。
3. **执行。**每个步骤成为一个待办事项，并在各自的工具循环中运行，受 `max_step_iterations` 和 `step_timeout` 限制。
4. **观察。**每一步之后，agent 会检查结果。检查的深度取决于 `reasoning_effort`。
5. **重新规划。**根据 `reasoning_effort` 的设置，当某一步失败或计划不再适用时，agent 会撰写新计划，最多 `max_replans` 次。
6. **回答。**agent 基于各步骤的结果生成最终答案。

计划保存在 agent 的执行状态中，不会添加到 task 描述里。

分步执行需要一个包含结构化步骤的就绪计划，规划器通过函数调用（function calling）获得这些步骤。如果在 `max_attempts` 之后计划仍未就绪，或者规划 LLM 不支持函数调用，agent 会改为运行其标准执行循环。

### 推理强度

`reasoning_effort` 控制每一步之后的行为：

| 级别 | 每步之后 | 成本 |
| --- | --- | --- |
| `"low"` | 启发式检查，不产生额外的 LLM 调用。失败的步骤被标记为失败，agent 按顺序继续执行，不重新规划。 | 最快 |
| `"medium"`（默认） | 由 LLM 审查该步骤。如果该步骤失败且审查认为计划已不再可行，agent 会重新规划；否则将该步骤标记为失败并继续执行。 | 均衡 |
| `"high"` | 由 LLM 审查该步骤，然后决定是提前结束、重新规划，还是完善剩余的步骤。 | 适应性最强，最慢 |

`observe_steps` 可在任意级别覆盖 LLM 审查行为：`True` 会为 `"low"` 添加审查，`False` 会从 `"medium"` 和 `"high"` 中移除审查。设置 `observe_steps=True` 时，当审查认为失败的步骤需要新计划，`"low"` 也会重新规划。

### 配置选项

<ParamField body="reasoning_effort" type="str" default="medium">
  控制 agent 在每一步之后检查和调整的程度：`"low"`、`"medium"` 或 `"high"`。
</ParamField>

<ParamField body="observe_steps" type="bool" default="None">
  在每一步之后运行 LLM 审查。`None` 表示仅在 `"medium"` 和 `"high"` 级别进行审查。
</ParamField>

<ParamField body="max_attempts" type="int" default="None">
  规划尝试的最大次数，包含首次规划。`None` 表示持续完善直到规划器将计划标记为就绪，这可能增加 LLM 调用次数。建议设置一个数值加以限制。
</ParamField>

<ParamField body="max_steps" type="int" default="20">
  要求规划器遵守的步骤数上限。它会以 `{max_steps}` 的形式传入提示词，但不会对返回的计划强制执行。必须至少为 1。
</ParamField>

<ParamField body="max_replans" type="int" default="3">
  在 agent 给出最终答案之前，允许完整重新规划的最大次数。`0` 表示禁用重新规划。
</ParamField>

<ParamField body="max_step_iterations" type="int" default="15">
  单个步骤允许的最大 LLM 迭代次数。数值越低，步骤越快但越不彻底。
</ParamField>

<ParamField body="step_timeout" type="int" default="None">
  单个步骤允许的最大秒数，在该步骤的每次 LLM 调用之前检查。超时后步骤会停止并返回目前已有的结果。该步骤不会被标记为失败，正在运行的 LLM 或工具调用也不会被中断。`None` 表示无超时。
</ParamField>

<ParamField body="llm" type="str | BaseLLM" default="None">
  用于规划以及每步之后审查的 LLM。`None` 表示使用 agent 自身的 LLM。
</ParamField>

<ParamField body="system_prompt" type="str" default="None">
  规划使用的自定义系统提示词。`None` 表示使用内置提示词。
</ParamField>

<ParamField body="plan_prompt" type="str" default="None">
  首次规划使用的自定义提示词。参见下文"自定义提示词"。
</ParamField>

<ParamField body="refine_prompt" type="str" default="None">
  完善计划时使用的自定义提示词。参见下文"自定义提示词"。
</ParamField>

下面的 agent 使用单独且更便宜的模型进行规划，并为循环的每个环节设置了上限：

```python
from crewai import Agent, PlanningConfig

researcher = Agent(
    role="Researcher",
    goal="Produce well-sourced research summaries",
    backstory="You are a meticulous researcher.",
    planning_config=PlanningConfig(
        reasoning_effort="high",
        max_attempts=2,
        max_steps=8,
        max_replans=2,
        max_step_iterations=10,
        step_timeout=120,
        llm="gpt-5.4-mini",
    ),
)
```

### 自定义提示词

`plan_prompt` 和 `refine_prompt` 使用 Python 的 `str.format` 进行填充。可用的占位符如下：

| 提示词 | 占位符 |
| --- | --- |
| `plan_prompt` | `{role}`、`{goal}`、`{backstory}`、`{description}`、`{expected_output}`、`{tools}`、`{max_steps}` |
| `refine_prompt` | `{role}`、`{goal}`、`{backstory}`、`{current_plan}`、`{max_steps}` |

如果你的提示词中省略了 `{max_steps}`，则不会对规划器施加步骤数限制。

```python
from crewai import Agent, PlanningConfig

writer = Agent(
    role="Technical Writer",
    goal="Write clear documentation",
    backstory="You turn complex systems into readable guides.",
    planning_config=PlanningConfig(
        max_attempts=2,
        plan_prompt=(
            "You are {role}. Your goal: {goal}.\n"
            "Plan how to complete this task in at most {max_steps} steps.\n"
            "Task: {description}\n"
            "Expected output: {expected_output}\n"
            "Available tools: {tools}"
        ),
        refine_prompt=(
            "You are {role}. Improve this plan and keep it to at most "
            "{max_steps} steps:\n{current_plan}"
        ),
    ),
)
```

<Warning>
使用任何其他占位符，或出现字面量 `{` 或 `}`，都会导致规划失败。此时 agent 会记录错误并在没有计划的情况下运行。字面量花括号请写作 `{{` 和 `}}`。
</Warning>

### 不依赖 task 的规划

当你直接用 `kickoff()` 调用 agent（不使用 `Task` 或 `Crew`）时，规划同样会运行。输入消息会被用作 task 描述：

```python
from crewai import Agent, PlanningConfig

planner = Agent(
    role="Travel Planner",
    goal="Plan practical trips",
    backstory="You plan efficient itineraries.",
    planning_config=PlanningConfig(reasoning_effort="low", max_attempts=1),
)

result = planner.kickoff("Plan a two-day trip to Lisbon on a mid-range budget.")

print(result.raw)
```

### `planning=True` 快捷方式

`Agent(planning=True)` 启用一个有界且低成本的配置。它等同于 `PlanningConfig(reasoning_effort="low", max_attempts=1)`：只进行一次规划尝试，且每一步之后不进行 LLM 审查。

```python
from crewai import Agent

agent = Agent(
    role="Data Analyst",
    goal="Analyze data and provide insights",
    backstory="You are an expert data analyst.",
    planning=True,
)
```

如果你同时传入了 `planning_config`，则以后者为准。

### 规划失败时

如果 agent 在规划过程中发生错误，错误会被记录，agent 会在没有计划的情况下运行 task。

<Note>
`reasoning=True` 和 `max_reasoning_attempts` 已被弃用。迁移方法请参阅[推理](/edge/zh-CN/concepts/reasoning)。
</Note>

## Crew 规划

启用 crew 规划后，在 task 运行之前，所有 crew 信息都会发送给 `CrewPlanner`。它会为每个 task 制定分步计划，并将计划添加到对应 task 的描述中。

### 使用 crew 规划

在你的 Crew 中添加 `planning=True`。每次 kickoff crew 时，`CrewPlanner` 都会撰写一份类似**Result**标签页中所示的计划，并将每个 task 对应的部分添加到该 task 的描述中：

<CodeGroup>
```python Code
from crewai import Agent, Crew, Process, Task

researcher = Agent(
    role="AI LLMs Senior Data Researcher",
    goal="Uncover cutting-edge developments in AI LLMs",
    backstory="You find the most relevant new work in AI LLMs.",
)

reporting_analyst = Agent(
    role="AI LLMs Reporting Analyst",
    goal="Create detailed reports based on AI LLMs data analysis and research findings",
    backstory="You turn research findings into clear reports.",
)

research_task = Task(
    description="Conduct a thorough research about AI LLMs",
    expected_output="A list with 10 bullet points of the most relevant information about AI LLMs",
    agent=researcher,
)

reporting_task = Task(
    description="Review the context you got and expand each topic into a full section for a report",
    expected_output="A fully fledged report with the main topics, each with a full section of information. Formatted as markdown.",
    agent=reporting_analyst,
)

# Assemble your crew with planning capabilities
my_crew = Crew(
    agents=[researcher, reporting_analyst],
    tasks=[research_task, reporting_task],
    process=Process.sequential,
    planning=True,
)

# Run the crew
my_crew.kickoff()
```

### 规划 LLM

Crew 规划默认使用 `gpt-5.4-mini`。将 `planning_llm` 设置为模型名称或 `LLM` 实例即可使用其他模型，例如 `Crew(..., planning=True, planning_llm="gpt-5")`。

<Warning>
使用默认的规划 LLM 时，crew 规划需要有效的 OpenAI API 密钥，即使你的 agent 使用其他提供商。如果你没有配置 OpenAI API 密钥，请将 `planning_llm` 设置为你可以访问的模型。
</Warning>
