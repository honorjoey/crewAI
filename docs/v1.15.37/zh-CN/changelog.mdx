  ## v1.15.29

  [在 GitHub 上查看此版本](https://github.com/crewAIInc/crewAI/releases/tag/1.15.29)

  ## 更新内容

  ### 重大变更
  - 移除 `CrewAgentExecutor`。`executor_class=CrewAgentExecutor` 现在会以 "CrewAgentExecutor has been removed" 报错，且以下导入路径已被移除：`crewai.agents.crew_agent_executor`、`crewai.agents.CrewAgentExecutor`、`crewai.experimental.agent_executor` 模块、`crewai.experimental.AgentExecutor` 以及 `crewai.experimental.CrewAgentExecutorFlow`。请从 `crewai.agents` 导入 `AgentExecutor`。
  - 改变每个 agent 的运行方式：过大的工具结果会被延迟写入临时文件，对话会在溢出上下文窗口之前进行摘要，第五次相同的工具调用会停止该 task。每项变更及其控制方式请参见[从早期版本升级 Agent](/zh-CN/concepts/agents#从早期版本升级-agent)。

  ### 新功能
  - 添加对 LiteLLM 兼容 kwargs 的支持。
  - 在 CLI 中实现平台应用搜索。
  - 在 CLI 的操作选择器中高亮搜索内容。
  - 在 flow 中追踪对话路由和公开回复。
  - 在 CLI 登录时选择组织。
  - 添加离线 jev 路由和护栏评估运行器。
  - 使用 call: 工具直接运行集成应用操作。
  - 将 AgentExecutor 从实验性状态转正。
  - 添加 Azure DocumentDB 向量搜索集成。
  - 添加只读 notebook 文本加载器和基于标准库的 jsonl 加载器。
  - 确保 crewAI eval 将评估的完整数据保留在项目中。
  - 支持 crewAI eval 通过一条命令自行运行 crew 以得出评估结论。
  - 允许 crewAI eval 将评估结果导出为文件。

  ### 问题修复
  - 修复从登录派生平台集成 token 的问题。
  - 通过在序列化错误时保留 JSON 日志来解决日志问题。
  - 跳过非 UTF-8 编码的缓存技能元数据。
  - 修复工具操作以遵循失败策略，并在每次 kickoff 时获取全新的使用额度。
  - 防止没有来源的私有记忆泄漏到每次召回中。
  - 修复 LanceDBStorage 中记忆记录的检索顺序。
  - 在重新规划失败时恢复 task 描述。
  - 阻止 agent 重复相同的工具调用。
  - 在 LanceDB 过滤器中转义 scope 和 id 值。

  ### 文档
  - 更新 crewAI 示例和可观测性指南中的失效链接。
  - 修复工具文档中的失效链接。

  ### 重构
  - 将上下文压缩重构为 BaseLLM 的能力。

  # CrewAI v0.1.0 发布说明

  我们非常激动地宣布 CrewAI 的首个版本 0.1.0 发布！CrewAI 是一个框架，旨在协调能够进行角色扮演和协作的自主 AI agent，以更高效地完成复杂任务。

  ## 新内容

  - **首次发布**：CrewAI 正式面世！这个奠基性版本为 AI agent 协同工作打下了基础，每个 agent 都有自己专门的角色和目标。

  - **基于角色的 Agent 设计**：使用特定的角色、目标及其成功所需的工具来定义和自定义 agent。

  - **Agent 间委派**：agent 现在能够自主委派 task，实现团队间工作量的动态分配。

  - **Task 管理**：动态创建和分配 task，并可灵活指定每个 task 所需的工具。

  - **顺序流程**：设置你的 agent 依次处理 task，确保工作流有序且可预测。

  - **文档**：通过我们的初始文档开始探索 CrewAI，它将指导你完成框架的设置和使用。

  ## 增强

  - `Agent`、`Task`、`Crew` 和 `Process` 类的详细 API 文档。
  - 帮助你构建第一个 CrewAI 应用的示例和教程。
  - agent 之间协作和委派机制的基础设置。

  ## 已知问题

  - 作为首个版本，可能存在尚未发现的问题和待优化之处。我们鼓励社区报告使用过程中发现的任何问题。

  ## 即将推出的功能

  - **高级流程管理**：在未来的版本中，我们将为 task 管理引入更复杂的流程，包括共识式和层级式工作流。
