# CrewAI AMP API

欢迎使用 CrewAI AMP API 参考文档。该 API 允许你以编程方式与已部署 crews 交互，并将其集成到应用、工作流和服务中。

## 快速开始

<Steps>
  <Step title="获取 API 凭证">
    在 CrewAI AMP 控制台中打开 crew 详情页，在 Status 标签中复制你的 ******。
  </Step>

<Step title="确认所需输入">
  使用 `GET /inputs` 端点查看 crew 期望的参数。
</Step>

<Step title="启动一次 Crew 执行">
  使用输入调用 `POST /kickoff`，启动执行并获得
  `kickoff_id`。
</Step>

  <Step title="监控进度">
    使用 `GET /status/{kickoff_id}` 查看执行状态并获取结果。
  </Step>
</Steps>

## 身份认证

所有 API 请求都需要使用 ****** 进行认证。请在 `Authorization` 请求头中携带 token：

```bash
curl -H "Authorization: ******" \
  https://your-crew-url.crewai.com/inputs
```

### Token 类型

| Token Type            | Scope                     | Use Case                                                     |
| :-------------------- | :------------------------ | :----------------------------------------------------------- |
| ********      | 组织级访问 | 具备完整 crew 操作权限，适合服务到服务集成 |
| **User ****** | 用户级访问        | 权限受限，适合用户特定操作   |

<Tip>
  两类 token 都可在 CrewAI AMP 控制台中 crew 详情页的 Status 标签找到。
</Tip>

## Base URL

每个已部署 crew 都有唯一 API 端点：

```
https://your-crew-name.crewai.com
```

将 `your-crew-name` 替换为控制台中的实际 crew URL。

## 典型工作流

1. **发现**：调用 `GET /inputs` 了解 crew 需要什么输入
2. **执行**：通过 `POST /kickoff` 提交输入并开始处理
3. **监控**：轮询 `GET /status/{kickoff_id}` 直到完成
4. **结果**：从完成响应中提取最终输出

## 错误处理

API 使用标准 HTTP 状态码：

| Code  | Meaning                                    |
| ----- | :----------------------------------------- |
| `200` | 成功                                    |
| `400` | 请求错误 - 输入格式无效         |
| `401` | 未授权 - bearer token 无效        |
| `404` | 未找到 - 资源不存在         |
| `422` | 校验错误 - 缺少必填输入 |
| `500` | 服务器错误 - 请联系支持团队             |

## 交互式测试

<Info>
  **为什么没有 “Send” 按钮？** 由于每个 CrewAI AMP 用户都有唯一 crew
  URL，我们使用 **reference mode** 而不是交互式 playground，以避免混淆。
  这样你可以准确看到请求格式，而不会遇到不可用的发送按钮。
</Info>

每个端点页面都会展示：

- ✅ **准确的请求格式**（包含全部参数）
- ✅ **响应示例**（成功与错误场景）
- ✅ **多语言代码示例**（cURL、Python、JavaScript 等）
- ✅ **认证示例**（正确的 ****** 格式）
